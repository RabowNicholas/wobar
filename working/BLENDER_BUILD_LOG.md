## 1. Rig and rules

**Rig (verified 2026-10-12, this is the M1 Max):** Blender **5.2** (5.2.2 on 2026-11-09) at `/Applications/Blender.app` · M1 Max, 32 GB · EEVEE for the HOHLWEG piece · user add-ons at `~/Library/Application Support/Blender/5.2/scripts/addons/`. The other machine has 4.5.3 at that same path and 5.2 at `Blender 5.2.app`: check `--version` before any headless run ([[reference/blender_library/BLENDER_FOOTGUNS]] V-1). Confirmed failures from the Everyday / MAKYO / kit work on the other machine are in FOOTGUNS V-1 – V-15, not here.

**MCP:** `mcp-for-blender` 2.1.9 (ahujasid), user scope, launched by Claude Code as `uvx mcp-for-blender` with `DISABLE_TELEMETRY=true`. Add-on file is `blender_mcp.py`, listed in Preferences as **Interface: MCP for Blender**. Socket on `localhost:9876`, no auth. Only works while Blender is open with the server started (N panel → MCP for Blender tab).

**Tools:** `execute_blender_code` (Python in the live session) · `look` (viewport / camera / multi-angle / render views) · `get_scene_info` · `search_assets` + `import_asset` (Poly Haven, Sketchfab, Poly Pizza) · `get_addon_status` · `generate_3d`.

**Rules (from the add-on's own docs, not yet tested here):**
- Never run `uvx mcp-for-blender` by hand in a terminal while Claude Code is using it. On a dead connection, restart both the Blender server and Claude Code.
- Poly Haven downloads block Blender's main thread — the UI freezes until done. Ask for 1k or 2k, never 4k+, in a live session.
- Long scripts time out. Build in small steps, one concern per call.
- Update with `uvx mcp-for-blender update` (server and add-on together).

**Working rules:**
- **Simulation caches go stale silently (repeated 2026-11-03, twice).** Any change to a curve, driver or tree that feeds a sim zone leaves the old bake in place, and reads/renders inside its range use the old state (a direction check read backwards). Rule: `simulation_nodes_cache_delete` after every upstream change, before any measurement or render.
- Inspect before building: `get_scene_info` first, never assume the scene is empty.
- After any visual change, `look` before reporting it done.
- The 5.x Python API moved things relative to most online examples. If an attribute or operator is missing, inspect it (`dir()`, `bpy.ops` listing) — don't guess a second name.
- Division of labour: Claude does plumbing (geometry along curves, scatter, rigs, drivers, MIDI/audio baking, render setup). Nick judges the image (lighting, fog, composition, asset choice).

## 3. Patterns that worked

Reusable snippets and recipes, proven in a session. Keep each short; put long scripts in `scripts/blender/` and link them.

- **Non-destructive sweep along a spine (5.2.2, proven 2026-10-13).** Empty mesh object + Geometry Nodes group: `Object Info (spine, RELATIVE)` → `Curve to Mesh` ← `Object Info (profile curve)` → `Transform Geometry (rot Z 180°)`; then `Flip Faces` → output. Editing either curve updates the mesh live. `Curve to Mesh` inputs in 5.2 are `Curve`, `Profile Curve`, `Scale`, `Fill Caps`.
- **Verify geometry by numbers, not screenshots.** `ob.evaluated_get(depsgraph).to_mesh()` → print bounds and a face normal → `to_mesh_clear()`. Faster and more reliable than `look` for "is it the right way up / the right size".
- **`look` in `angles` mode frames from outside the target.** It is poor for judging an interior like the lane; use the scene camera (`mode: camera`) once one is placed.
- **Camera on the spine at constant speed (proven 2026-10-13).** `FOLLOW_PATH` with `use_fixed_location=True`, `use_curve_follow=False`; object's own location is the offset from the curve (z = eye height); keyframe `constraints["Follow Path"].offset_factor` linearly → measured speed constant to ±0.01 m/s through bends. Aim = an Empty on the same curve with the same constraint, offset ahead by `metres / spline.calc_length()`, plus `TRACK_TO` (−Z, up Y) on the camera.
- **Keyframe interpolation in 5.x:** `action.fcurves` is gone. Reach F-curves via `action.layers[*].strips[*].channelbag(ob.animation_data.action_slot).fcurves`.
- **Read positions from the evaluated object** — `ob.evaluated_get(depsgraph).matrix_world` after `frame_set`. Right after adding constraints, `ob.matrix_world` on the original returned stale values for every frame.
- **`look` (frames / camera view) does not honour a changed render aspect and does not draw overlays** — a 1080×1920 scene still came back as landscape tiles, and a wire guide parented to the camera was invisible. For true-aspect stills: temporarily switch to `BLENDER_WORKBENCH`, set resolution, `bpy.ops.render.render(write_still=True)` to the scratchpad, restore engine/resolution in a `finally`, then read the PNGs. Workbench frames of the blockout render in well under a second.
- **9:16 guide in the camera:** a 4-edge wire rectangle parented to the camera at z = −1, sized for a frame of width 1, with scale x/y driven by `sensor_width / lens` so it survives lens changes. `hide_render`, `hide_select`, `show_in_front`.
- **Vertical finding (blockout, 28 mm):** a centre 9:16 crop of the 16:9 frame keeps only 31.6% of the width (~23° horizontal) and loses a wall in every bend; a native 1080×1920 render from the same camera (sensor fit AUTO) is ~40° horizontal and holds both walls.
- **`search_assets` is verbose** — ~12 lines per result. Use `limit` ≤ 5 and one specific query per role; four 12-result searches in one turn was wasteful.
- **Poly Haven textures (proven 2026-10-13):** `import_asset(asset_type="textures", resolution="2k", apply_to=[obj])` builds a Principled material named after the asset id (Diffuse, Rough, Normal, Displacement) with a POINT-mode Mapping node. Set Mapping Scale = surface metres ÷ the texture's real-world size (reported in the result) for life-size tiling, and set `use_fake_user` so a rejected-then-wanted material survives a save. Six 2k imports ran back to back without a timeout.
- **Line-up method for choosing assets:** candidates on 4 m patches in an `ASSETS/LINEUP` collection parked at x ≈ −45, a temporary sun (`TMP_LineupSun`), then `look` angles/top with `shading="rendered"`.
- **Poly Haven coverage for a forest (searched 2026-10-13):** strong on ground textures, roots, stumps, logs, ferns, moss; trees are fir, pine, jacaranda and small coastal trees only — no beech/oak-type broadleaf.
- **Poly Haven models (proven 2026-10-13):** `import_asset(asset_type="models")` lands at the origin in a new top-level collection named after the asset id — or `<id>_LOD0` when the asset has LODs, so find it with `startswith(id)`. The result message gives no object names or sizes; list new objects yourself. Multi-piece assets arrive as several objects (`root_cluster_02` = 8, `pine_roots` = 2, `dry_branches_medium_01` = 3). Scans are heavy: root clusters 160k–340k polys, stump 41k, dead trunk 83k.
- **Poly Haven "root" assets are scanned ground patches** — roots on a slab of soil (reddish on the root clusters), not free-standing roots. They sit on a surface; they don't hang down a wall.
- **Poly Haven trees arrive as LOD0 only and are very heavy (measured 2026-10-13):** `pine_tree_01` a/b/c = 5.8M / 3.5M / 5.0M polys · `fir_tree_01` a/b/c = 2.1M / 1.2M / 0.26M · `fir_sapling_medium` a/b/c = 0.35M / 0.21M / 0.22M. Each asset is three separate trees, 6–20 m tall, plain meshes (no modifiers) with 3–4 materials. `import_asset` gives no way to ask for a lower LOD. Do not scatter LOD0 trees — get a lighter version first (decimate, or fetch the asset's lower LOD files directly).
- **Getting a lower LOD (proven 2026-10-13):** `curl https://api.polyhaven.com/files/<id>` → `blend.1k.blend.url` is one .blend holding every LOD (`<id>_<a|b|c>_LOD0/1/2`). Download it to `/Volumes/music/blender/hohlweg_assets/polyhaven/`, then `bpy.data.libraries.load(path, link=False)` and append only the LOD1/LOD2 objects. The append brings `.001` duplicate materials with broken texture paths — re-point each slot to the already-imported material of the same base name, then remove the unused duplicates. Result: fir a/b/c LOD1 = 89k / 65k / 35k, LOD2 = 48k / 42k / 22k; sapling LOD1 = 10k / 6k / 6k. LOD1 reads as full as LOD0 from 20 m.
- **Imported textures are packed into the .blend.** Their `filepath` points at a temp folder (`/var/folders/…/blender_mcp_polyhaven_*`), which looks fragile, but `image.packed_file` is set on every one (75 of 75). No relocation needed; check `packed_file` before worrying.
